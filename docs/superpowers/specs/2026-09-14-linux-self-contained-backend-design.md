# Frxe Desktop Self-Contained Backend + Cross-Platform Packaging Design

Date: 2026-09-14

## Goal

Make Frxe Desktop build reliably from this repository alone and add first-class Windows, Linux, and macOS distribution from one shared Tauri/Rust backend. The project must no longer depend on downloading the deleted pinned backend repository at build time.

## Current problem

The frontend and adapter live in `Frxe-Windows`, but `src-tauri/` is generated by `tools/prepare-backend.ps1` from repository id `1367264568` at commit `5e8cec3611514bc73037bbf195efa066d6dd3fb8`. That source now returns GitHub 404, so the MSI workflow cannot build even though frontend checks pass.

`package.json` is also Windows-specific: backend preparation shells out to PowerShell and `tauri:build` requests only an MSI. This prevents normal Linux and macOS CI paths.

## Chosen approach

Vendor the required Rust/Tauri backend into this repository under `src-tauri/` and treat it as normal source code. Remove the remote backend bootstrap from the build path. Keep the existing JavaScript command adapter contract so the current UI does not need a platform-specific rewrite.

The same Tauri backend will be compiled on Windows, Linux, and macOS. Platform-specific behavior will be isolated behind Rust `cfg` gates only where necessary, such as tray behavior, file-opening details, native path conventions, or dependency installation helpers.

## Native backend responsibilities

The self-contained backend must provide the commands already used by `web/backend.mjs`:

- `innertube_search` with `music` and `web` clients
- `ytdlp_search`
- `resolve_stream_url`
- `scan_downloads`
- `clear_removed_downloads`
- `download_already_exists`
- `download_track`
- `cancel_download`
- `remove_download`
- `fetch_metadata_lyrics`
- `update_runtime_dependencies`
- `set_tray_enabled`
- `download-progress` events

YouTube Music remains the first search source. Regular YouTube and yt-dlp remain fallbacks.

The backend must not contain credentials or signing secrets. Runtime helpers such as yt-dlp/FFmpeg may be discovered or downloaded only through explicit app logic and must fail with clear user-facing errors if unavailable.

## Playback and skip behavior

The existing frontend resolver cache and adjacent-track prefetch remain authoritative for fast Next/Previous behavior. The backend's `resolve_stream_url` command should resolve one track as efficiently as possible and return a directly playable URL. No platform-specific playback queue implementation will be introduced.

## Packaging

### Windows

Keep the existing x64 MSI target and filename:

`Frxe-Desktop-0.1.0-x64.msi`

`build.bat` will build directly from checked-in `src-tauri/` and will no longer fetch a backend snapshot.

### Linux

Add Linux build scripts and CI targeting x86_64 Linux. Tauri will produce both:

- `Frxe-Desktop-0.1.0-amd64.deb`
- `Frxe-Desktop-0.1.0-x86_64.AppImage`

The `.deb` is the primary installer for Debian/Ubuntu-family systems. The AppImage is the portable distribution for other compatible x86_64 Linux distributions.

The Linux CI runner will install the normal Tauri/WebKitGTK build dependencies before compiling. Packaging must use the same Frxe icon, product name, publisher, application identifier, and frontend assets as Windows.

### macOS

Add macOS build scripts and CI for both current Mac CPU families. Tauri will produce DMG installers for:

- `Frxe-Desktop-0.1.0-macos-arm64.dmg` for Apple Silicon Macs
- `Frxe-Desktop-0.1.0-macos-x64.dmg` for Intel Macs

Both builds use the same Frxe UI, native backend, application identifier, and icon assets. No separate macOS feature fork will be introduced.

The default CI output is unsigned and unnotarized so the project can build without private Apple credentials. This means macOS Gatekeeper may show the normal warning for an unidentified developer. Apple Developer ID signing and notarization can be added later through repository secrets without committing certificates or credentials.

## Build commands

`package.json` will become platform-neutral at its core:

- `npm run check` — shared test and syntax validation
- `npm run tauri:dev` — direct Tauri development from checked-in backend
- `npm run tauri:build:windows` — MSI
- `npm run tauri:build:linux` — DEB + AppImage
- `npm run tauri:build:macos` — DMG for the active macOS architecture

The obsolete `backend:prepare` dependency will be removed from normal build and development commands. `tools/prepare-backend.ps1` will be removed once its remaining branding/config behavior is incorporated into checked-in Tauri configuration.

## CI

Keep the Windows workflow and add Linux and macOS workflows. All workflows must run `npm run check` before native compilation.

Windows artifact:

`Frxe-Desktop-0.1.0-Windows`

Linux artifact:

`Frxe-Desktop-0.1.0-Linux`

macOS artifacts:

- `Frxe-Desktop-0.1.0-macOS-Apple-Silicon`
- `Frxe-Desktop-0.1.0-macOS-Intel`

The Linux artifact contains both the `.deb` and `.AppImage`. Each macOS artifact contains its architecture-specific `.dmg`. CI fails if any expected package is missing.

## Error handling

Native commands should return descriptive errors rather than panic. Network-source failures should preserve the existing fallback behavior where applicable. A failure to resolve one provider must not crash the app.

Platform-specific helper failures must explain what dependency or capability is unavailable rather than silently disabling playback/download behavior.

Build workflows must fail immediately when required native dependencies are absent or a package cannot be staged. They must not upload partial artifacts as successful releases.

## Testing and verification

Keep the existing 19 frontend/adapter tests and syntax checks. Add backend-focused tests where practical for command parsing, fallback ordering, path handling, and platform-neutral logic.

Completion requires all of the following:

1. `npm run check` passes.
2. Windows GitHub Actions produces the MSI from the checked-in backend with no remote backend fetch.
3. Linux GitHub Actions produces both the `.deb` and `.AppImage`.
4. macOS GitHub Actions produces both the Apple Silicon and Intel `.dmg` installers.
5. The built app retains YouTube Music-first search, volume control, support links, readable selects, and fast queue skip behavior across all three desktop operating systems.
6. No tracked build output, private signing material, credentials, Apple certificates, or temporary backend-download files are committed.

## Non-goals

This migration does not redesign the Frxe UI, add a second playback engine, add ARM Linux packages, add Flatpak/Snap packaging, create a universal macOS binary, add Apple Developer signing/notarization credentials, or change the current product version beyond `0.1.0`. Those can be separate follow-up work.
