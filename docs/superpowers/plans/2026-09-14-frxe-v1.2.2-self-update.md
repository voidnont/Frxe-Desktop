# Frxe Desktop v1.2.2 Self-Update Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Frxe Desktop v1.2.2 with no Windows console windows, Home support links, signed cross-platform self-updates, and fresh Windows/Linux/macOS installers published to GitHub Releases.

**Architecture:** Keep the existing Tauri v2 desktop architecture and add the official `tauri-plugin-updater` at the native/plugin boundary. The frontend owns update UX, Tauri validates signatures and installs packages, and GitHub Actions signs platform update artifacts and generates a static `latest.json` consumed by the app.

**Tech Stack:** Tauri v2, Rust, vanilla ESM frontend, Node test runner, GitHub Actions, GitHub Releases.

**Spec:** `docs/superpowers/specs/2026-09-14-frxe-self-update-v1.2.2-design.md`

## Global Constraints

- Version is exactly `1.2.2` everywhere user-visible and package-visible.
- The updater endpoint is `https://github.com/voidnont/Frxe-Windows/releases/latest/download/latest.json`.
- Updater signatures are mandatory and use Tauri's signing key format.
- Commit only the updater public key; never commit the private key or password.
- GitHub Actions secrets are named `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.
- Windows main executable uses the GUI subsystem in release builds.
- Windows child processes for yt-dlp/FFmpeg/runtime checks use `CREATE_NO_WINDOW`.
- Preserve all existing five user-facing packages: MSI, DEB, AppImage, macOS arm64 DMG, macOS x64 DMG.
- Publish updater metadata only after all required platform builds for the same commit succeed.
