# Frxe Desktop v1.2.2 Release + Self-Update Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Frxe Desktop v1.2.2 with clean per-platform build organization, no Windows console windows, Home support links, signed cross-platform self-updates, five verified installers, and a cleaned `Frxe-Desktop` repository.

**Architecture:** Keep one shared Tauri v2 application in `web/` and `src-tauri/`. Put operating-system-specific local build/package entry points under `platforms/windows/`, `platforms/linux/`, and `platforms/macos/`; GitHub Actions orchestrates those platform folders. The official Tauri updater validates signed GitHub Release artifacts, while the Frxe frontend presents check/download/install/restart state in Settings.

**Tech Stack:** Tauri v2, Rust, vanilla ESM frontend, Node test runner, GitHub Actions, GitHub Releases.

**Spec:** `docs/superpowers/specs/2026-09-14-frxe-self-update-v1.2.2-design.md`

## Global Constraints

- Canonical repository is exactly `voidnont/Frxe-Desktop`.
- Version is exactly `1.2.2` everywhere user-visible and package-visible.
- The updater endpoint is `https://github.com/voidnont/Frxe-Desktop/releases/latest/download/latest.json`.
- Updater signatures are mandatory and use Tauri's signing-key format.
- Commit only the updater public key; never commit the private key or password.
- GitHub Actions secrets are exactly `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.
- Windows main executable uses the GUI subsystem in release builds.
- Windows child processes for yt-dlp/FFmpeg/runtime checks use `CREATE_NO_WINDOW`.
- Preserve these five user-facing packages: MSI, DEB, AppImage, macOS arm64 DMG, macOS x64 DMG.
- Keep shared application source in `web/` and `src-tauri/`; do not duplicate it across platform folders.
- Platform-specific local build/package files belong under `platforms/windows/`, `platforms/linux/`, or `platforms/macos/`.
- Project-facing files must not contain AI/generated-by/development-chat provenance text.
- Do not alter Git history or remove legally required notices.
- Do not publish updater metadata until every required platform build for the same source commit succeeds.
- Post-release cleanup starts only after the v1.2.2 release and updater assets are verified.
